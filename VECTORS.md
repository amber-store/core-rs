# Golden vectors

`tests/golden/` holds cross-implementation test vectors generated by the **Go**
implementation (`tools/vectorgen`, pinned to `github.com/amber-store/core`
`v0.0.10-0.20260923125338-91da3cf24ab7` in its `go.mod`; regenerating at
that pin reproduces every older file byte for byte).
The Rust test suite consumes them to prove byte compatibility. Regenerate with:

```sh
cd tools/vectorgen && go run . ../../tests/golden
```

Every file below is deterministic: regenerating must produce identical bytes.

## Deterministic data streams

Pseudo-random payloads are derived from **splitmix64**:

```
next(state): state += 0x9E3779B97F4A7C15
             z = state
             z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9
             z = (z ^ (z >> 27)) * 0x94D049BB133111EB
             return z ^ (z >> 31)
```

`data(seed, n)`: initialize `state = seed`; repeatedly append `next(state)` as
**8 little-endian bytes**; truncate to `n` bytes.

`u64s(seed, n)`: the first `n` outputs of `next` from `state = seed` (used for
filter inputs).

In JSON, a payload is described as `{"kind":"splitmix","seed":S,"len":N}`,
`{"kind":"const","byte":B,"len":N}` (N copies of byte B), or
`{"kind":"concat","parts":[...]}`.

## Files

### `keys.json`

```json
{ "cases": [ { "type": 0, "length": "12345", "payload": {..}, "key": "<64 hex>" } ] }
```

`length` is a decimal string (may exceed 2^53). The key is
`key.New(type, length, data(payload))`. Includes: length 0 special case, all
five types, length-field sizes 1–8, and cases where `length` ≠ payload length
(logical lengths).

### `ultracdc.json`

```json
{ "cases": [ { "name": "...", "min": 0, "normal": 0, "max": 0,
               "data": {..}, "chunks": [2048, 777, ...] } ] }
```

`min`/`normal`/`max` of 0 select the library defaults (32768/524288/1048576).
`chunks` are the byte lengths of the chunks produced by `chunkers.SplitBytes`,
in order; their sum equals the input length. An empty input has `"chunks": []`.
Cases include: empty, 1 byte, `min`, `min+1`, exactly `max`, several-MiB
splitmix data, constant (low-entropy) data hitting the LEST path, and
concatenations that mix both.

### `item_chunker.json`

```json
{ "cases": [ { "bits": 7, "items": [ {..payload..}, ... ], "runs": [128, 5, ...] } ] }
```

Feed each item encoding to `ItemChunker.IsBoundary(enc, runLen)` in order,
where `runLen` counts items in the current run **including** the current one;
a `true` result closes the run. `runs` are the resulting run lengths, with the
final (possibly unterminated) run included. Cases cover bits 0, 4, 7, 10.

### `fstree/` — the golden tree

A fully specified in-memory tree built with default parameters
(`item_bits = 7`, ultracdc defaults, `xattr_inline_max = 256`). Both
implementations build it through their public builder APIs
(file: `SplitBytes` → `EncodeBlob`s → `NewFileIndexBuilder` promotion when >1
blob; directory: `NewDirBuilder` over entries pre-sorted bytewise by name).

- `fstree/manifest.json`:

```json
{ "root": "<64 hex>",
  "objects": [ { "key": "<64 hex>", "size": 123 }, ... ] }
```

`objects` is the deduplicated set of every emitted object, sorted by key hex.

- `fstree/objects.bin`: for each object in manifest order:
  `key (32 bytes) ‖ big-endian u64 byte length ‖ object bytes`.

**Tree definition.** Root directory entries (listed here unsorted; builders
receive them sorted bytewise by name). `mt(s, ns)` below means mtime
`s*1e9 + ns` nanoseconds; uid/gid default 1000/1000, files mode 0o100644,
dirs 0o40755 unless stated. Any metadata field not stated is zero — in
particular every root-table entry (including the `sub` and `bigdir`
directories themselves) has mtime 0.

| name | kind | details |
|------|------|---------|
| `empty` | file | 0 bytes |
| `small.txt` | file | `data(1, 100)` |
| `medium.bin` | file | `data(2, 30000)` (a single chunk at the default sizes) |
| `big.bin` | file | `data(3, 5242880)` (5 MiB, a file index over several blobs) |
| `constant.dat` | file | `const(0xAA, 300000)` (low-entropy chunking) |
| `A-upper` | file | `data(4, 10)` (sorts before lowercase) |
| `\xc3\xa9-utf8` | file | `data(5, 10)` (name is "é-utf8" in UTF-8) |
| `sub` | dir | see below |
| `bigdir` | dir | see below |

`sub` entries (uid 0, gid 0 unless stated):

| name | kind | details |
|------|------|---------|
| `ln` | symlink | target `../small.txt`, mode 0o120777, mt(1600000000, 500) |
| `fifo` | fifo | mode 0o10644, mt(1600000001, 0) |
| `sock` | socket | mode 0o140644, mt(1600000002, 0) |
| `chr` | chardev | rdev [1, 3], mode 0o20644, mt(1600000003, 0) |
| `blk` | blockdev | rdev [259, 0], mode 0o60644, mt(1600000004, 0) |
| `xattr-inline` | file | `data(6, 50)`, mode 0o100600, uid 501, gid 20, mt(1500000000, 123456789), inline xattrs `{"user.a": data(7, 5), "user.b": data(8, 100)}` |
| `xattr-spilled` | file | `data(9, 50)`, mt(1500000001, 0), xattrs `{"user.big": data(10, 400)}` (400 > 256 ⇒ spilled `XattrSet`) |
| `old` | file | `data(11, 10)`, mt(-1, 999999999) (negative mtime) |
| `setuid` | file | `data(12, 10)`, mode 0o104755, uid 4294967294, gid 4294967294 |

`bigdir`: 3000 regular-file entries named `e%06d` for i in 0..2999, content
`data(1000+i, i mod 50)` (60 of them empty ⇒ dedup), mode 0o100644,
uid 1000, gid 1000, mt(1700000000 + i, i).

Xattr spill rule (from Go `ingest/driver.go`, `buildEntry`): xattrs stay
inline iff the serialized canonical CBOR xattr map is ≤ 256 bytes
(`len(enc) <= xattrInlineMax`), else the map becomes an `XattrSet` object
referenced by key 9.

### `amberpack/`

- `records_raw.json`:

```json
{ "cases": [ { "key": "<64 hex>", "payload": {..}, "record_blake3": "<64 hex>",
               "record_hex": "..." } ] }
```

Records whose splitmix payloads do **not** compress (flag stays 0), so bytes
are implementation-independent. `record_hex` present only for payloads
≤ 256 bytes; `record_blake3` always. Includes the empty payload.

- `records_compressed.json`: Go-encoded records with compressible payloads —
  decode-only vectors (Rust must parse and recover the payload; byte equality
  is **not** expected from a Rust encoder):

```json
{ "cases": [ { "record_hex": "...", "key": "<64 hex>", "payload": {..} } ] }
```

- `pack_go.bin`: a wire pack written by Go containing **every object of the
  golden fstree** (manifest order). Rust must stream-decode it, recover every
  object byte-exactly, and observe the end marker. Also `pack_empty.bin`: magic
  + end marker only.

### `filters.json`

```json
{ "cases": [ { "n": 100, "seed": 42, "section_blake3": "<64 hex>",
               "section_hex": "..." } ] }
```

Inputs are `u64s(seed, n)` **deduplicated and sorted** (as packstore does).
The section is exactly packstore's filter section: `0x01` type byte ‖ u64 BE
seed ‖ u32 BE SegmentLength ‖ u32 BE SegmentLengthMask ‖ u32 BE SegmentCount ‖
u32 BE SegmentCountLength ‖ u32 BE fingerprint count ‖ big-endian u16
fingerprints. `section_hex` present for n ≤ 100. n covers
{1, 2, 3, 10, 100, 1000, 10000, 123456}.

### `segments_go/`

A packstore directory written by Go with a small segment-size option so it
contains **two sealed segments and one unsealed active segment** (the store was
killed without Close/seal — vectorgen truncates any footer if needed and
documents the method in its source). Plus `segments_go/manifest.json`:

```json
{ "segment_size": 65536,
  "objects": [ { "key": "<64 hex>", "payload": {..} } ],
  "absent": [ "<64 hex>", ... ] }
```

`objects` lists every stored key with its payload derivation; `absent` lists
canonical keys that must report not-found. The Rust store must open this
directory, serve every object, pass a full verify/scrub, and report the absent
keys missing.

### `reference.json`

```json
{ "cases": [ { "name": "...", "key": "<64 hex>", "user": "...",
               "created_at": "1700000000000000000",
               "signature_hex": "...", "public_key_hex": "...",
               "bytes_hex": "..." } ] }
```

`created_at` decimal string (int64, ns). `signature_hex`/`public_key_hex`
optional. Cases include: minimal (empty user, no signature), unicode name with
`/`, max-length name (1024 bytes), and a signed-shape record (opaque dummy
signature bytes). `bytes_hex` is the canonical encoding; both encode (must
equal) and decode (must round-trip) are tested against it.

### `commit.json`

```json
{ "cases": [ { "name": "...", "tree": "<64 hex>", "parents": ["<64 hex>"],
               "author":    { "name": "...", "email": "...",
                              "when": "1700000000000000000", "tz_offset": 120 },
               "committer": { "...": "same shape" },
               "message": "...",
               "signature_hex": "...", "public_key_hex": "...",
               "bytes_hex": "...", "key": "<64 hex>",
               "signature_payload_hex": "..." } ] }
```

`when` decimal string (int64, ns); `tz_offset` minutes east of UTC.
`signature_hex`/`public_key_hex` optional. `key` is the commit's key: type 5
with the length field set to the byte length of `bytes_hex`.
`signature_payload_hex` is the canonical encoding without the signature
field. Cases include: two root commits and the merge over them (the vector
annotated in `architecture/commits.md`), a signed-shape record (opaque dummy
signature bytes), a public key without a signature, an octopus merge of 24
parents with a `DirNode` tree, unicode identities, 1024-byte identity
strings, a negative timestamp and both extreme offsets, and an empty message
with no email. Encode, key and signature payload must equal; decode must
round-trip.

### `tar_go.tar`

`tarexport.Write` of the golden fstree (root not emitted; socket entries
skipped). The Rust exporter must produce **byte-identical** output.

### `amberignore.json`

```json
{ "cases": [ { "name": "...",
               "files": [ { "dir": "", "lines": ["*.log", "!keep.log"] } ],
               "checks": [ { "path": "a/b.log", "is_dir": false, "ignored": true } ] } ] }
```

`dir` is the directory containing the `.amberignore` file relative to the scan
root (`""` = root). Semantics follow the Go `amberignore` package (gitignore:
negation, `**`, directory-only `name/`, anchored `/name`, last match wins,
subtree scoping). The Go implementation is the oracle; cases cover each
feature and composition across levels. Each check is evaluated the way the
ingest walk asks the matcher: descend from the root creating a child matcher
per directory; if any ancestor directory of the path is `Ignored` the path
reports ignored (the subtree is pruned — re-inclusion under an ignored
directory is impossible); otherwise the final component's `Ignored(name,
is_dir)` answer is recorded.
